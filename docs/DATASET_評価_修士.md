# 修士研究に向けたデータセット評価(仮置き版)

対象: Kaggle等から集めた14データ + 学部GDELTデータ。
研究の前提: 「テキストを入れると株価予測の精度が上がるか」を検証する。入力はテキスト+数値(価格はyfinance)。目的変数は未定。
**仮置き**: 市場は問わない/予測単位はデータが対応できる単位/時間軸は日次を基準/目的変数は価格から再定義できる前提。
根拠は、これまでの実データ検証です(未検証の点は「要確認」と明記)。

## 1. 評価軸
| 軸 | 意味 |
|---|---|
| R1 日付・時刻 | ニュースを取引日・引け前後に正しく対応付けられるか(リーク防止) |
| R2 対応単位 | 銘柄/指数/セクターのどれに結べるか |
| R3 期間 | 長さ、直近まであるか、市場環境の多様さ(局面) |
| R4 規模 | 学習・検証に足りるサンプル数 |
| R5 テキスト | 見出しのみか本文か、ノイズ、重複 |
| R6 価格 | yfinanceで取れるか(または既に付属しているか) |
| R7 ラベル | 目的変数を自分で作り直せるか(既存ラベルに依存しないか) |

## 3. 組み合わせによるカバー評価

### 3-1. 単体の弱点(何が足りないか)
| データ | 足りないもの |
|---|---|
| news_price_events | 2020年6月以降、本文、AAPL/AMZNなど大型株 |
| NYT見出し | 銘柄対応、2022年以降、本文 |
| master_quant(DB) | ニュース密度・銘柄対応(ニュース側が薄い) |

### 3-1b. news_price_eventsの弱点の重大度(検証後の見直し)
| 弱点 | 重大度 | 理由 |
|---|---|---|
| 2020年6月以降がない | 中 | 「テキストが効くか」の検証には11年・218銘柄で足りる。ただし、(a)現在の市場への一般化、(b)最新LLMが当時のニュースと値動きを学習済みの可能性(汚染)、(c)テスト期間にコロナ急落が入る点が問題。他市場(インド・ベトナムの〜2025/26)での頑健性確認で補える |
| 本文がない | 低 | 研究の問いは「テキストが価格予測を改善するか」であり、見出しで検証可能。学部でも本文は見出しより良くなかった。本質的な制約は、見出しの質(汎用見出しが34%) |
| AAPL/AMZN/MSFT/META/JPM/XOM/INTC/AMD/WMTが0行 | 低〜中 | 223銘柄はセクターが分散(GOOGL/NVDA/NFLX/TSLA/BAC/KOなどは含む)。問題は「なぜその銘柄か」という選定理由が不明な点(選択バイアスの可能性) |
| **本当に重い点** | **高** | ラベルの対応が1日ずれる疑い(ニュース当日の反応が対象外)、`time_window`の定義が不明、汎用見出し、同一日の行が独立でない、終値しかない |

### 3-2. 組み合わせ案
| 案 | 構成 | 結合キー | 補えるもの | 残る穴 | 評価 |
|---|---|---|---|---|---|
| **US-1** | news_price_events + NYT見出し(+ yfinance価格) | 日付(NYTを市場コンテキストとして銘柄日に付与) | 銘柄固有ニュース+市場全体ニュース。重なる期間は2009〜2020で、両者の寄与を分けて検証できる | 2020年以降、本文 | **◎ 最も実現性が高い** |
| **VN-1** | master_quant(価格・マクロ) + archive (15) CafeF(+ Google News 7千件) | 日付+銘柄コード | 価格・マクロ・直近(〜2025-09)・銘柄対応(20%)がそろう。9年超 | 時刻、本文、ベトナム語NLP、yfinance取得可否(要確認) | **○ 新規性が高いが前処理が重い** |
| **IN-1** | News_sentiment + stock_news(2022〜) + yfinance指数(^NSEI等) | 日付(指数単位) | 2017〜2026の長期市場ニュース | 2021-05〜12の空白、媒体の継ぎ目、銘柄対応なし | **△ 指数予測に限る** |
| **CROSS** | US-1 と VN-1(必要ならIN-1) | 同じ手法を別市場に適用(行は結合しない) | 「成熟市場と新興市場で、テキストの効果は違うか」を比較できる。単一市場の結論の一般化を補強 | 作業量が大きい。言語が異なる | **○ 修士の差別化に有効(段階的に)** |
| LONG | SP500_Alpha + EDGARで過去の10-Kを追加取得 | 提出日(新規取得が必要) | 本文(長文)、低頻度、クロスセクション | 現データだけでは3年で不足。取得作業が必要 | △ 別方向の拡張 |
| 不可/冗長 | news_price_events + SP500_Alpha / NYT + Kaggle DJIA / 米国 + インド(行結合) | - | - | 期間が重ならない/情報が重複/市場が違う | × |

要点:
- **どの組み合わせも「時刻つき・銘柄対応・本文・直近・大規模」を全部は満たしません。**
- 最も穴が少ないのは **US-1**(時刻・銘柄・規模・長期を確保。穴は直近と本文)。
- **VN-1** は直近まで揃い、価格側が強い一方、言語とテキストの密度が課題です。
- 結合は、**同一市場内で日付をキーにする**ものだけが成立します。

## 4. 共通の注意(設計に直結)
1. **yfinanceの分足・時間足は取得期間が限られます**(時間足は直近約2年、分足は数日〜60日。要確認)。2009〜2020の時刻つきニュースは、**日次の価格に対応付ける**形になります。時刻は「その日の引け前か後か」を決めるために使います。
2. **ベースラインを必ず置く**: 価格のみ(前日のボラティリティ、銘柄効果など)のモデルと、テキストを足したモデルを同じ分割で比べます。news_price_eventsでは、前日の変動とラベルの順位相関が0.32あり、価格だけで一定の精度が出ます。
3. **サンプルの独立性**: 同一日・同一銘柄の行は同じラベルを共有する(news_price_events: 1日1.38窓)ため、日単位でtrain/testを分けます。
4. **期間の局面差**: テスト期間にコロナ急落(2020)が入ると分布がずれます。複数のwalk-forward窓で評価します。
5. **ラベルは自分で作り直す**: `Target_Buy`(ベトナム)、`forward_return`(絶対値のみ)、NYTの`Label`(S&P500の翌日)は、そのまま使いません。
