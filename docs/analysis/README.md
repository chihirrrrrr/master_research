# 分析メモ(docs/analysis/)

1回の分析ごとに1ファイル。「何のデータで・どう分析し・何が出て・何が言えるか」を、あとから単独で読めるように残す。

## ファイル名
`YYYYMMDD_<研究>_<データ>_<モデル>.md`
- 例: `20261015_study1_A0m_numeric_xgboost.md`(2026-10-15 / 研究1 / 数値のみ / XGBoost)
- 研究 = study1(市場) / study2(銘柄)。データ = A0m, A1m(+NYT), A0〜A3 など。

## 構成(この順)
1. 概要(何を調べたか・1行結論)
2. データセット(行・期間・何個の変数か)
3. 説明変数(名前と意味)
4. 目的変数
5. モデルと設定
6. データの分け方(学習/テスト/検証の割合・年・空き)
7. 結果(数値)
8. 考察(言えること・言えないこと)
9. 再現(実行コマンド・runディレクトリ・設定ファイル)

## 指標の読み方
| 指標 | 意味 | 見方 |
|---|---|---|
| 学習行 / テスト行 | その回の学習・テストの日数 | テスト行が少ないほど、結果はぶれる |
| R²(標本外R²) | 1 − Σ(実現−予測)² / Σ(実現−履歴平均)² | 0より大きい = 履歴平均より良い。0は「平均を答えるのと同じ」。負は平均より悪い |
| 相関 | 予測と実現値の相関 | 0なら無関係。正なら、大小の方向が合っている |
| 正解率 / 的中率 | 予測の符号(上昇/下降)が実現の符号と一致した割合 | **「いつも上昇」の割合と比べる**。同じなら、何も当てていない |
| balanced accuracy | 上昇日・下降日を同じ重みで見た的中率 | 0.5 = 当てずっぽう |
| AUC | 予測値の大小で上昇日を当てる力 | 0.5 = 偶然。0.5未満は、順序が逆 |
| 上昇と予測した割合 | 予測が正の日の割合 | 100%に近い = 「いつも上昇」に近い |
| 予測sd / 実現sd | 予測値と実現値のばらつき(bp) | 予測sdが実現sdよりずっと小さい = ほぼ定数の予測 |
| Clark–West p | 履歴平均より良いかの片側検定(5日平均の重なりをHAC補正) | 小さいほど「履歴平均より良い」(通常 0.05以下)。多数の比較をしたときは補正が必要 |
| R²_in | 学習データ側の R² | テスト側との差で、過学習・学習不足を見る |

## reg1 と reg2
XGBoost の「複雑さの上限」を変えた2つの設定。reg2 の方が、より強く複雑さを抑える。

| | reg1 | reg2 |
|---|---|---|
| 木の深さ | 1〜2 | 1(切り株) |
| 葉の最小サンプル | 50〜100 | 100〜200 |
| 学習率 | 0.02 | 0.01 |
| L2正則化 | 50 | 200 |
| subsample | 0.7 | 0.6 |
→ reg2 は予測を平均に強く引き寄せる(ほぼ定数になる)。reg1 は少し柔軟だが、年により当たり外れが大きい。
